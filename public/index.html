Getting started

A Flare is a style for your name in chat: colours, images, glow and motion. Making one takes a few minutes.

  1. Design it. Open Flare studio, type your name above the canvas and pick a template. You can try everything without an account.
  2. Make it yours. Set colours and images in Fill, glow and shadows in Effects, animation in Motion, and weight and spacing in Lettering.
  3. Check it at chat size. The small preview under the canvas is the size people will actually see.
  4. Submit it. In Publish, sign in with Twitch, Kick or YouTube, name the Flare, confirm the artwork is yours and submit.
  5. Wear it. A moderator reviews it and you get a notification. Once it’s approved, press Equip in Collection or on Discover.

Nameflare never changes your name on Twitch, Kick or YouTube. Your Flare appears next to your name in chat tools that support Nameflare (see API & chat apps).

Troubleshooting

Quick fixes for the problems people run into most.

My Flare doesn’t show in chat
  • Check that it’s approved and equipped in Collection.
  • Check that the platform you’re chatting on is linked under Account → Connected platforms.
  • The chat tool itself has to support Nameflare. Twitch, Kick and YouTube don’t show Flares on their own.
  • Changes can take up to 15 seconds to reach chat tools.
I can’t submit my Flare
  • You need to be signed in and to tick the artwork-rights box.
  • Each account can have 3 Flares, including disapproved ones (artists can have 20). See Publishing & review.
  • Every image layer needs a file, and a Flare can use one GIF and one still image.
  • Fix any field marked as invalid, such as a colour that isn’t a hex code.
  • If an image was “flagged” or “not allowed”, the server’s scanner refused it. Use a different image.
My image disappeared in the studio

Drafts and JSON files don’t keep image files, so reattach them after a reload or import. If the file is still attached, check the layer’s type is Image, its opacity, and that no solid layer above it is covering it. Paused previews and reduced-motion mode show a still fallback on purpose.

It looks different in chat than in the studio

Set the studio’s Chat font size and Preview font to match your chat. The large view is magnified; the small one is the real size. Some chat tools don’t support every effect yet.

Signing in fails

Start again from the Sign in button rather than going back in the browser. YouTube sign-in needs a Google account with a YouTube channel. “Setup required” means the site’s operator hasn’t turned that platform on yet. Never share a sign-in link that contains a code.

“Too many requests” or “Connection interrupted”

The site retries on its own when it’s busy. Wait a few seconds and press Try again. Clicking very fast or opening many tabs at once can trigger this.

I was suspended or banned

A suspension ends by itself after 1, 3, 7 or 30 days. Until then you can’t sign in or make changes. If you think a ban is a mistake, contact the site’s operator.

Layers & images

The fill inside your letters is a stack of up to six layers.

Layers

  • The layer at the top of the list is painted on top. New layers are added underneath.
  • Each layer is Solid (one colour), Linear (colour along an angle), Radial (outward from a point), Conic (around a point) or Image.
  • A solid, fully opaque layer hides everything below it. Lower its opacity, move it down, or pick a blend mode: Screen brightens, Multiply darkens, Overlay and Soft light add contrast.
  • Duplicate, reorder or remove layers from the list. Undo brings back anything you removed.

Gradients

  • Each gradient has 2 to 12 colour stops. Drag them along the bar, and use the alpha slider (or an #RRGGBBAA code) for transparency.
  • Scale and Position move the gradient, not the text. Repeating the gradient and tiling the canvas are separate switches.

Images

  • Use a GIF, PNG, WebP, JPEG or BMP up to 2 MB and 2048 × 2048 pixels.
  • A Flare can use one GIF and one still image. Using the same file on several layers counts once.
  • Start with just an image makes a fill that is only your picture.
  • Crop & position: drag or use the arrow keys to pan, zoom in, or press Cover to fill the name without stretching. Your file itself isn’t changed.
  • Images stay in your browser until you submit. The server then rebuilds each one, which removes location data, camera details and anything hidden in the file. JPEGs are turned upright and BMPs are stored as PNG.

Drafts and files

  • Ctrl/⌘ + S saves a draft in this browser. Export JSON and Import JSON move a design between browsers or people.
  • Neither keeps image files, so reattach images after a reload or import.
  • Picking a preset replaces the whole design. Press Undo if you didn’t mean to.

Effects & preview

Effects are drawn around the letters. Check them at real chat size before you submit.

Effects

  • Glow, Outline and Drop shadow, plus up to 8 extra shadows in the shadow stack.
  • 3D depth extrudes the letters by up to 8 steps.
  • Sizes are in pixels, so large values can swamp small text. Check readability on both light and dark backdrops.

Motion

  • Flow scrolls the gradient in a seamless loop, Shimmer sweeps a highlight across, Pulse fades gently, and Spectrum cycles through the colour wheel.
  • Play it forward, in reverse, or back and forth (ping-pong).
  • Solid colours and images don’t flow. GIFs play on their own.
  • People who ask their device for reduced motion see a still version automatically. Pause stops the preview while you work.

Lettering

Adjust the weight and letter spacing. The text itself always stays the person’s real name.

Preview

  • Preview font shows your name in another font, including the whole Google Fonts catalog. Only the font you pick is downloaded, from Google. It changes the preview only, because chat tools use their own font.
  • Chat font size: set it to the size your chat uses.
  • Switch the backdrop between dark, light and transparent to see how it reads everywhere.
  • The big view is magnified. The small one is the real size.

Publishing & review

A moderator checks every Flare before anyone else can see or wear it.

Submit

  1. Open Publish in the studio and sign in.
  2. Name the Flare and add a description if you like.
  3. Choose Public (listed in Discover) or Unlisted (only people with the link find it; it isn’t secret).
  4. Confirm the artwork is yours to use and submit.

Limits

  • Each account can have 3 Flares, counting pending, approved and disapproved ones. Artists can have 20.
  • Disapproved Flares count until they’re deleted, one year after the decision.
  • Moderators’ and the owner’s Flares are approved straight away and have no limit.

Review

  • Moderators check that you have the right to the artwork, that nothing is harmful, that the name is readable at chat size, and that nothing flashes.
  • The bell tells you when it’s decided, and Collection shows where each Flare is.
  • A disapproved Flare comes with a note. Press Revise to open it in the studio, fix it and submit again.
  • Once approved you can equip and share it, and switch it between Public and Unlisted in Collection.
  • A Flare that breaks the rules can be removed later. Anyone wearing it goes back to their plain name.

Discover & wear

Find Flares you like, wear one, and follow the people who make them.

  • Discover: search by name, filter by motion, and sort by newest, trending this week, most liked, most equipped or name. Switch between a grid and a feed.
  • Type your name in Preview as at the top of Discover to see every Flare with it.
  • Open a Flare to share its link, download it as JSON to edit a copy, or report it.
  • Like with the heart. Your likes keeps them together.
  • Equip to wear it. You wear one Flare at a time, on every platform you’ve linked.
  • Creators: find people by name or platform username and follow them. Following shows their new Flares, and Artists features the site’s artists.
  • The bell shows likes, new followers and review decisions.
  • Insights (under More) shows your likes, profile views, wearers and followers over time.

Sign-in & linked accounts

Sign in with Twitch, Kick or YouTube. There’s no password and no separate sign-up.

  • Your first sign-in creates your account.
  • To wear your Flare on more platforms, link them under Account → Connected platforms while signed in. You can link one account per platform.
  • To change one, open Change next to it: Switch to another account on that platform (your Flare moves with you), Refresh your name and picture, or Unlink it. You always keep at least one, because that’s how you sign in.
  • When switching, the platform asks which account to use. If it signs you straight back in as the same one, sign out on that site first.
  • A platform account that’s already linked to another Nameflare account can’t be taken over. Sign in to that account and unlink it there first.
  • The owner’s and moderators’ accounts keep Twitch linked, because staff access is tied to a Twitch ID. They can still switch to another Twitch account.
  • YouTube sign-in needs a YouTube channel on that Google account.
  • Under Account → Edit profile, set your bio and accent colour, and pick which platform your name and picture come from. Sign in through that platform again to refresh them.
  • Renaming yourself on a platform doesn’t break anything, because accounts are matched by their platform ID.

Nameflare only asks platforms who you are. It never posts in chat, never keeps platform access tokens, and never changes your name there.

Appearance

Change how Nameflare looks under More → Appearance. Your choice is saved in this browser.

  • Themes: Ink (the default), Paper, Sand, Dusk, Frost, Moss, Plum and Rose. Press T anywhere to cycle through them.
  • Custom: pick a background and an accent colour, and everything else is worked out from them. Text switches between light and dark to stay readable, and you’re warned if the accent is hard to see.
  • Density: Compact fits about twice as many Flares and rows on screen.
  • Interface motion: Reduced turns off interface animation. Flares follow your device’s reduced-motion setting.

Flare previews always keep their own colours, whatever theme you use.

Privacy & your data

What Nameflare keeps, for how long, and how to download or delete it.

What Nameflare keeps

  • Your account: name, avatar, bio and accent, and the platform accounts you connect (their public ID, login and display name). No passwords and no platform access tokens are kept.
  • What you make and do: your Flares, the images you upload, your likes and follows, and your notifications.
  • Page views: daily counts per page only, with no address, account or device attached. Do Not Track and Global Privacy Control turn them off.
  • Sign-in sessions: a random cookie, stored only as a hash, that expires after a week.
  • Networks: a scrambled fingerprint (keyed hash) of the network you sign in or make changes from, never the address itself, kept 90 days. It is used only so that a ban also covers the networks a banned account used.

Uploaded images

Every image is opened and rebuilt before it is stored. Location data, camera details, comments and anything hidden after the picture are removed. Images stay private until a moderator approves the Flare that uses them, and the operator can also scan uploads for malware and unsafe content.

Reporting a Flare or a profile

Use Report on a Flare’s page or on a profile. Moderators see every report and can dismiss it, remove the Flare (and block its images from coming back), or ban the account. The person you report is never told who reported them.

Download or delete your data

Go to Account → Your data. Download my data gives you everything above as one JSON file. Delete my account removes your profile, connected platforms, Flares (including ones other people wear), images, likes, follows and notifications straight away; it cannot be undone. Reports you sent stay, without your name, and moderation history notes that an account was deleted. Backups roll off within 14 days.

Moderating

How moderators and the owner keep Nameflare safe, including when several of you work at once.

Roles

Owner
One account, set on the server by its Twitch ID. Can do everything, including adding moderators and artists under Moderation → Accounts.
Moderators
Review Flares, handle reports, and ban, suspend or delete regular and artist accounts. They can’t review their own Flares or act on other moderators.
Artists
A blue badge, 20 Flares instead of 3, and a place on the Artists page. No moderation access; their Flares are still reviewed.

Reviewing

  • Moderation → Review queue shows the oldest submissions first. Filter it to Flares the scanner flagged, reported ones, ones with images, or creators who had a disapproval before.
  • Each submission shows the Flare at real size, its full recipe, the creator’s history (approved, disapproved and pending counts, open reports, recent disapproval notes) and your team’s notes about them.
  • Approve, or Disapprove with a note the creator will read. Quick notes fill in common reasons, and you can save your own.
  • Undo from the toast (or U) within 10 minutes, as long as nobody has changed it since. The creator’s notification is taken back too.
  • Tick several submissions (or press X) to approve or disapprove them all with one note.

Working with other moderators

  • You see who is looking at what, such as “nova looking”. It’s a heads-up, not a lock.
  • Moderation pages update every few seconds. Anything someone else decided is marked, and its buttons switch off.
  • If someone decided first, you’re told who and when, and your click doesn’t overwrite theirs.
  • N and the automatic advance skip items someone else is already handling.
  • Closing a report only closes the reports you were shown. Any that arrive meanwhile stay open.

Reports

Moderation → Reports groups reports by Flare or profile. Dismiss them, remove the Flare (its images are then blocked from being uploaded again), or ban the account.

Accounts

  • Each row in Moderation → Accounts has a Manage menu.
  • Staff notes: private notes the whole team can see, such as warnings or follow-ups.
  • Ban or suspend: for 1, 3, 7 or 30 days, or permanently. Either one signs the person out and blocks sign-in through every linked platform and from the networks they recently used. Suspensions end by themselves and keep the person’s Flares; permanent bans take the Flares down. Lifting a ban doesn’t bring them back.
  • Delete account: removes the account and everything in it, with a reason, but doesn’t ban the person. They can sign up again.
  • Banned accounts and the moderator list are under Moderation → Bans & team. Only the owner can ban moderators.

Activity log

Every decision, ban, deletion and role change is recorded. Filter it by moderator, search it, press Only me for your own actions, or export it as CSV or JSON. Disapproved Flares can also be deleted permanently from the queue. That can’t be undone.

API & chat apps

Any app that shows chat can show Flares, using the free public API.

  • No key is needed, any website can call it, and it only returns approved Flares.
  • Look people up by their platform ID (Twitch or Kick user ID, YouTube channel ID), never by display name.
  • Support in Banechat ↗ isn’t out yet. Chatterino would need an add-on that doesn’t exist yet.

Main endpoints

GET  /api/v1/users/twitch/:user_id      what someone is wearing
GET  /api/v1/users/kick/:user_id
GET  /api/v1/users/youtube/:channel_id
POST /api/v1/resolve                    up to 100 IDs at once
     {"provider":"twitch","ids":["123","456"]}
GET  /api/v1/cosmetics                  approved, public Flares
GET  /api/v1/cosmetics/:id
GET  /api/v1/cosmetics/:id/wearers      who is wearing it now
GET  /api/v1/stats                      site totals and top Flares

An unknown ID returns 404 (or is left out of a batch), and someone with nothing equipped has cosmetic: null. Show their normal name in both cases. /api/config lists the canonical addresses.

Drawing Flares

  • Use client.js, or renderer.js with effects.css, on a text-only name element.
  • Never insert recipe data as HTML or raw CSS, and respect reduced motion.
  • Check again at least every 15 seconds, so removed Flares disappear.

Every endpoint, including profiles, stats and the full recipe format, is in the API reference on GitHub ↗.

Running your own server

Nameflare is open source (AGPL-3.0). The official site runs Node and SQLite behind nginx on a small Oracle server.

  1. Try it locally. With Node 22.13 or newer, run npm run demo for a copy with sample accounts and Flares.
  2. Configure it. Copy .env.example to .env and set your site address, data folder, and your own numeric Twitch ID as OWNER_TWITCH_ID. That account becomes the owner.
  3. Turn on sign-in. Register an app with each platform you want (steps below) and put the client IDs and secrets in .env. Keep secrets out of the repository and screenshots.
  4. Go live. Follow the server runbook ↗: HTTPS with nginx and its rate limits, the system service, and nightly backups.
  5. Run it. The operations guide ↗ covers malware and content scanning, restoring backups, load testing and moderating as a team. Publish your own contact details next to the privacy notice ↗.

Sign-in apps

Each platform needs its callback address registered exactly, on your HTTPS address: /auth/twitch/callback, /auth/kick/callback and /auth/youtube/callback. Restart Nameflare after saving credentials.

Twitch
  1. In the Twitch developer console ↗, register an application.
  2. Add https://your-site/auth/twitch/callback as the OAuth redirect URL.
  3. Set TWITCH_CLIENT_ID and TWITCH_CLIENT_SECRET.
Kick
  1. In Kick Developers ↗, open account settings → Developer and create an application.
  2. Add https://your-site/auth/kick/callback as the redirect URL. If it asks for scopes, user:read is enough.
  3. Set KICK_CLIENT_ID and KICK_CLIENT_SECRET.
YouTube
  1. In Google Cloud Console ↗, create a project and enable YouTube Data API v3.
  2. Under Google Auth Platform, set up Branding and Audience. Choose External, and add test users while the app is in Testing.
  3. Under Data Access add https://www.googleapis.com/auth/youtube.readonly. Under Clients create a Web application client with redirect URI https://your-site/auth/youtube/callback.
  4. Set YOUTUBE_CLIENT_ID and YOUTUBE_CLIENT_SECRET. An API key or service account won’t work.
  5. Until Google verifies the app, only your test users can sign in.
