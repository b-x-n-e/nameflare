Create, publish, and use your Flares.

1. Create your first Flare

  1. Open Flare studio and pick a template under the canvas. You can edit and preview without signing in.
  2. Type a preview name above the canvas. Shape the fill from the Fill list: add layers, drag gradient stops, or drop in an image you own.
  3. Switch on effects (glow, outline, drop shadow, shadow stack, 3D depth) and tune each one in the inspector; Lettering sets weight and spacing. Check the actual chat-size preview, not just the magnified view.
  4. Choose Publish, name the Flare, confirm artwork rights, and submit while signed in.
  5. Track the decision in My collection. After approval, equip it there or in Discover.

Approval makes a Flare shareable; public listing puts it in Discover. Unlisted Flares remain accessible to anyone with their link. You can change listing in My collection; equipping assigns it to your linked identities. Neither step modifies your Twitch, Kick, or YouTube display name.

2. Layers, gradients, and GIFs

Use up to six layers. The first layer is on top. New layers are added underneath. A fully opaque Normal layer can cover everything below it; lower its opacity, move it down, or choose a blend mode. Screen brightens, Multiply darkens, and Overlay / Soft light add contrast. Blending stays isolated to the name.

  • Linear: color along an angle. Radial: color outward from a center. Conic: color around a center. Solid: a single RGBA color.
  • Each gradient accepts 2–12 stops. Set positions from 0–100%, and use #RRGGBBAA or the alpha slider for transparency.
  • Scale changes the fill canvas, not the name's font size. Position aligns that canvas. Gradient repeat and canvas tiling are separate controls.
  • Image: choose up to one distinct GIF and one distinct PNG/WebP per Flare, each up to 2 MB with a canvas no larger than 2048 × 2048. Reusing the same file across layers counts once. Select an image layer to replace its file. Crop & position shows its fill canvas: drag or use arrow keys to pan, adjust zoom, or choose Cover without stretching. Shift+arrow moves farther. At 100% size there is no space to pan on that axis. These settings do not edit the original image bytes; extreme aspect ratios are limited by the 500% canvas-size bound. Choose Start with just an image for an image-only fill without gradients or extra effects. Preview is local; upload happens when you submit.

Attached-file buttons show images across all layers. Moving, duplicating, or temporarily changing a layer's type keeps its attached image in this editing session. Switch back to Image to restore it. Removing a layer removes it from the recipe; Undo restores it. Image animation is independent of the gradient animation selector.

Save draft and Export JSON preserve recipe settings, not local image bytes. Reattach files after a reload or import. Presets replace the design; use Undo if you changed one accidentally.

3. Preview at the size your chat uses

Choose a Preview font to compare your name in different typefaces, then set Chat font size to your overlay's font size (the built-in OBS overlay uses 18px). Font selection changes only the live previews and crop guide, not your saved Flare or another client's font. Search the full bundled Google Fonts catalog, then select a family in Preview font. Only the selected family is downloaded—not the entire catalog. Google Fonts choices contact Google’s font CDN; local/system choices do not, and Bricolage Grotesque is served locally. Loading errors fall back to the system font with a Retry button. System font availability varies. The bundled catalog is a snapshot; operators can refresh it with npm run fonts:update. Inspection zoom magnifies that same render, including its shadows and outline, rather than making a different large-font Flare. The lower preview is shown at actual size.

Seamless Flow closes the palette and shifts it by exactly one gradient repeat; conic layers turn through 360°. Shimmer makes a continuous, linear sweep with a closed color loop, Pulse gently changes opacity, and Spectrum cycles hue through a full turn while retaining glow and shadows. Choose Forward, Reverse, or Ping-pong playback. Solid colors and image fills do not scroll in Flow; GIF playback remains independent. Letter spacing adjusts the whole name without changing its text.

Glow, outline, and shadow offsets are pixel values. Increasing them can overwhelm small text. Check readability on both light and dark backdrops. A different client font, letter spacing, or font size can still change the result; integrations must match the renderer and typography.

Up to eight extra shadows can be stacked. Depth is a lightweight text extrusion, not a 3D scene. Pause motion stops CSS animation and replaces animated image fills with the fallback palette; it does not freeze a GIF frame. Reduced-motion visitors get static fallback fills automatically.

Studio keyboard shortcuts

These shortcuts work while Flare studio is open and no dialog is active. On Windows/Linux use Ctrl; on macOS use ⌘ for the commands below. Select a layer by opening its panel or focusing one of its controls.

Alt + ↑ / ↓

Gradient stop or angle dial: ← / → (Shift for bigger steps), Home / End
Nudge the focused gradient stop or turn the focused angle dial. Home / End move a stop to the start or end of the bar; Delete removes it.

Text inputs, textareas, and select menus keep normal typing, arrows, deletion, and native undo. Save draft and Alt+1–5 still work there. Contenteditable fields and input-method composition are left alone. Browser or operating-system shortcuts may take priority.

Image crop keyboard controls

Focus the Crop & position image stage and use arrow keys to pan by 5 preview pixels, or Shift + arrow for 20 pixels. These crop controls replace layer nudging while the stage is focused. At 100% fill size there may be no room to pan; zoom in or use Cover first. Elsewhere in the studio, arrows nudge the selected layer’s percentage position.

4. Sign in and link accounts

Anyone can create an account: the first sign-in with an enabled provider automatically registers a regular user, with no invitation or separate password. Returning users sign in through the same provider. Then link other platforms from My account while still signed in. Twitch and Kick use numeric account IDs; YouTube uses a channel ID. Renaming a platform account does not change the identity key.

OAuth verifies identity on the provider's own page. Nameflare does not ask for passwords and does not retain provider access tokens. Kick requests user:read; YouTube requests read-only channel access, so a YouTube channel is required. Twitch does not request chat-posting permissions.

Your verified platform name and avatar are copied to Nameflare. Choose a connected platform as your profile source in My account, and sign in through that platform again to refresh it. Unsupported or missing profile images use an initial instead.

One identity per provider can be linked to an account. An identity already linked elsewhere cannot be silently merged. Sign out to access that account. Unlinking, merging, account deletion, and data export are not implemented yet. Local demo accounts are isolated samples, not real OAuth logins.

If a provider says “setup required,” the operator has not supplied its client credentials. Register exact callbacks under the canonical HTTPS origin: /auth/twitch/callback /auth/kick/callback /auth/youtube/callback

Operator: enable Kick sign-in
  1. Open Kick Developers, then account settings → Developer and create an application.
  2. Register https://nameflare.bxne.dev/auth/kick/callback as the redirect URL for this host. If using another origin, substitute its exact HTTPS origin. Permit user:read if the dashboard asks for scopes; no chat-write permission is needed.
  3. Privately set KICK_CLIENT_ID and KICK_CLIENT_SECRET on the server, then restart the Nameflare service. Kick authorization uses PKCE automatically.
Operator: enable YouTube sign-in
  1. Create/select a project in Google Cloud Console. Enable YouTube Data API v3.
  2. Configure Google Auth Platform → Branding and Audience. Choose External for public users and add test users while the app is in Testing.
  3. Under Data Access add https://www.googleapis.com/auth/youtube.readonly. Under Clients create a Web application OAuth client with redirect URI https://nameflare.bxne.dev/auth/youtube/callback.
  4. Privately set YOUTUBE_CLIENT_ID and YOUTUBE_CLIENT_SECRET and restart Nameflare. An API key or service account is not a substitute.
  5. Test with a Google account that owns a YouTube channel. Complete Google's required publication/verification before promising unrestricted public YouTube sign-up; Testing only permits approved test users.

Keep all secrets outside source and screenshots. Restart only after credentials are saved. OAuth linking does not add Kick/YouTube live-chat connectors.

5. Publication and moderation

Pending designs and their images are private to the creator and reviewers. Reviewers check artwork permission, harmful content, readability, and flashing motion. Moderator and owner submissions are approved automatically. Moderators cannot manually review their own Flares; the owner can review any Flare, including their own. Rejection includes feedback; edit a copy to make a new submission.

Approved public Flares appear in Discover and the public API catalog. Sign in and click a heart to like a Flare, or click it again to unlike. Each account counts once. Liked Flares keeps your favorites together; Most liked sorting highlights community favorites without changing approval. Approved unlisted Flares can be viewed and equipped through their shared link; their recipes and assets are not private. Revocation removes them and clears equipped assignments. Clients must revalidate within the 15-second cache window. Editing a copy does not inherit approval.

The owner role is bootstrapped by a configured numeric Twitch ID—not a username or the first signup. Only the owner can assign moderators from the accounts table or by numeric Twitch ID after that account signs in. The moderation board filters pending, approved, and disapproved Flares and shows full recipes, creator identities, submission/review times, reviewer names, and decision notes. Nameflare reviewer roles are separate from a channel's Twitch moderator status. Moderators can search accounts and ban/unban regular users; only the owner can ban/unban moderators. All account bans are permanent: they have no automatic expiry and persist across server restarts. They end sessions, block sign-in through every connected identity, hide public profiles, and revoke the account’s Flares. Moderation → Settings contains the searchable banned-account list, reasons, and ban dates. Staff can explicitly lift a ban; unbanning never restores sessions or Flare approvals. The owner bypasses account quotas and app throttling, but safe upload/recipe checks remain. On the Oracle/Node service, moderators and the owner can permanently delete disapproved Flares from Moderation. Their recipes and image files used by no other Flare are removed; an audit event and existing backups remain. This has no in-app undo. Decisions, deletions, bans, and role changes are audited. Search User profiles to see public connected identities and equipped Flares.

6. Add chat to OBS

  1. Your OBS source URL is /overlay?channel=yourchannel on this site, with your Twitch channel login in place of yourchannel.
  2. In OBS, add a Browser Source, paste that URL, and choose your canvas dimensions (for example 700 × 900).
  3. The overlay joins public Twitch chat anonymously. No streamer password or OAuth token belongs in the source URL.
  4. Send a chat message from an account with an approved, equipped Flare. The overlay resolves its immutable Twitch user ID.

Sample overlay uses labeled test messages. The direct Twitch overlay handles reconnects and message deletion. For Kick, YouTube or other chats, create a relay room under Integrations & API. Your own connector posts each chat message to the room with the room’s token; the room’s overlay link shows them. Nameflare does not supply the connectors. Keep posting tokens on your server and overlay links private; New keys replaces both at once.

Banechat's existing site is a separate project. Direct Nameflare integration and its redesign require that project's source; links alone do not install Flares into it. Stock Chatterino also requires a native adapter, which is not shipped.

7. Integrate the public API

Approved reads require no key and allow CORS. Discover the canonical API at /api/config. Do not key Flares by display names, and never render imported recipe data as HTML or arbitrary CSS.

GET /api/v1/cosmetics?limit=60&offset=0
GET /api/v1/cosmetics/:id
GET /api/v1/users/twitch/:numeric_id
GET /api/v1/users/kick/:numeric_id
GET /api/v1/users/youtube/:channel_id
POST /api/v1/resolve
{"provider":"twitch","ids":["123","456"]}

Batch resolve accepts at most 100 string IDs. Unknown identities are omitted from the batch result; a single unknown identity returns 404. A linked user without an equipped Flare has cosmetic: null. Fall back to the platform's normal name when resolution fails.

Browser clients can use the shared renderer and effect stylesheet. Apply a returned cosmetic to a text-only name element and pass the canonical service origin for textures. Keep authoritative text intact, respect reduced motion, and revalidate instead of retaining a revoked Flare indefinitely. Native clients need their own safe implementation of the bounded recipe format.

Never put a session cookie, OAuth secret, CSRF token, or relay ingest token in public client code. Private creator/moderation writes require a signed-in same-origin session and CSRF token.

Privacy, safety and your data

What Nameflare keeps

  • Your account: name, avatar, bio and accent, and the platform accounts you connect (their public ID, login and display name). No passwords and no platform access tokens are kept.
  • What you make and do: your Flares, the images you upload, your likes and follows, and your notifications.
  • Page views: daily counts per page only, with no address, account or device attached. Do Not Track and Global Privacy Control turn them off.
  • Sign-in sessions: a random cookie, stored only as a hash, that expires after a week.

Uploaded images

Every image is opened and rebuilt before it is stored. Location data, camera details, comments and anything hidden after the picture are removed. Images stay private until a moderator approves the Flare that uses them, and the operator can also scan uploads for malware and unsafe content.

How long things are kept

  • Notifications: 180 days.
  • Page-view counts: about 13 months.
  • Disapproved Flares: deleted a year after the decision.
  • Images no Flare uses: deleted 7 days after upload.
  • Report details: cleared 90 days after a report is closed; the report itself goes after a year.
  • Moderation history: 2 years.
  • Nightly backups: 14 days.

Reporting a Flare or a profile

Use Report on a Flare’s page or on a profile. Moderators see every report and can dismiss it, remove the Flare (and block its images from coming back), or ban the account. The person you report is never told who reported them.

Download or delete your data

Go to Account → Your data. Download my data gives you everything above as one JSON file. Delete my account removes your profile, connected platforms, Flares (including ones other people wear), images, likes, follows, notifications and relay rooms straight away; it cannot be undone. Reports you sent stay, without your name, and moderation history notes that an account was deleted. Backups roll off within 14 days.

8. Operator setup: Oracle and OAuth

The official Nameflare service runs on Oracle with Node, SQLite, private filesystem textures, and Nginx HTTPS. A Cloudflare Worker adapter is available separately; it is not the official runtime.

  1. Use a canonical HTTPS hostname you control. Keep the Node listener private behind Nginx and the database/textures in persistent storage.
  2. Back up data before updates. Node applies additive migrations on startup; preserve the private environment and existing accounts.
  3. Register Twitch, Kick, and Google OAuth apps. Enable YouTube Data API v3, configure the consent screen/test users, and complete any verification required by Google.
  4. Store client secrets in the private server environment. Never put them in this site, a repository, or a screenshot.
  5. Deploy only after reviewing costs and domain ownership. Test new login, account linking, cancellation, expired state, owner bootstrap, moderation, and revoked textures on the live HTTPS origin.

The deployment runbook is in the source on GitHub ↗. Public launch still needs upload decoding/frame limits, abuse reporting, privacy procedures, backups, and monitoring. Header validation is not malware scanning. No live login or internet deployment is implied by local test results.

9. Troubleshooting

My GIF disappeared

Check attached-file buttons. Select its layer, switch the type back to Image, and check opacity/order. An opaque upper layer can hide it without deleting the file. After a reload or JSON import, reattach the original file. Pause or reduced-motion mode intentionally uses a static gradient fallback.

My preview looks different in chat

Match the chat font size and font family. Inspection zoom is not the export size. Check that the client supports all recipe fields and has loaded the shared effect stylesheet. Missing/pending images are private; only approved assets are public.

My equipped Flare does not appear

Verify the correct platform account is linked, the Flare is approved and equipped, and the integration uses the official API and immutable IDs. Wait up to 15 seconds for revalidation. Banechat and stock Chatterino do not automatically gain support merely because a Flare is equipped.

OAuth returns an error

Check the exact callback hostname/path and client credentials. Restart after cancellation, expiry, switching accounts during login, or clearing cookies. YouTube needs a channel and any required test-user access. Do not share callback URLs containing authorization codes.

Submission was blocked

Sign in, confirm artwork rights, fill every image slot, and fix invalid numeric/hex fields. Regular accounts can have three submitted Flares total; artists can have 20 on the official Oracle/Node service. Limits count pending, approved, rejected, and unlisted designs. The owner grants or removes the blue Artist role from Moderation → Accounts. Artist submissions still require review and the role grants no moderation access. Existing extras are preserved. Moderators and the owner are exempt from the Flare limit. The separate texture library allows 50 files; the owner is exempt from that texture quota. All designs use the safe format: six layers, at most one GIF plus one PNG/WebP image, eight extra shadows, and 12 gradient stops per layer. Moderator and owner submissions are approved automatically.
